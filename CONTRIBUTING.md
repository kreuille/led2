# Contribuer à LED2

## Flux de travail

1. Décrire le besoin ou le bug dans une issue.
2. Créer une branche dédiée.
3. Implémenter un changement ciblé.
4. Tester le parcours concerné et les cas d'erreur.
5. Mettre à jour la documentation si nécessaire.
6. Ouvrir une pull request avec le contexte, les captures utiles et les tests effectués.

## Commits

Utiliser des messages courts et explicites, par exemple :

- `feat: add WLED connection client`
- `fix: handle unavailable device`
- `docs: update setup instructions`

## Pull requests

Une pull request doit expliquer le problème résolu, les choix importants et la manière de vérifier le résultat. Les changements visuels doivent inclure une capture avant/après lorsque c'est pertinent.
